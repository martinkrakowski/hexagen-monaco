# ADR-0050: Empty Hexagonal Barrels and Frozen No-Code Scaffolds

**Date:** 2026-08-14
**Status:** Proposed
**Type:** Architecture
**Supersedes:** ADR-0007-barrel-generation-consolidation.md (Implementation section — specifically the `export {};` empty-layer-barrel convention decided at its line 110 and the "Barrel Generation After Fix" diagram at lines 126-146)
**Relates to:** ADR-0026-sync-generator-safety-hand-written-preservation.md (hand-written preservation guarantees), ADR-0007-barrel-generation-consolidation.md (single-walker barrel doctrine, which stays intact)

## Context

Three related conditions in the current tree contradict AGENTS.md and the audit's HEX-025/HEX-035 findings, and one of them is a _decided convention_ that must be formally retired rather than treated as drift.

### 1. Empty `export {};` layer barrels are pervasive — and were deliberate

`rg '^export \{\s*\}' packages --glob '**/src/**/*.ts'` matches **31 files across 14 packages** on the current tree (recomputed 2026-08-14; per-package: architectural-enforcement 3, code-generation 3, core-domain 3, deployment 3, layout-engine 1, manifest-generation 2, mcp-server 1, messaging 1, model-settings 3, monaco-orchestration 1, persistence 3, runtime 3, ui 3, wizard-orchestration 1).

Of these 31, the marker breakdown is **19 / 9 / 3** (not 19 / 9 as the C4 draft and the audit both stated): **19 carry `// @generated by @hexagen/sync`**, **9 carry the older `// Minimum content to prevent TS2306 "not a module" error`** comment (e.g. `packages/architectural-enforcement/src/domain/index.ts:1-2`, whose two-line header is `// domain layer barrel — generated by sync.ts` / `// Minimum content to prevent TS2306 "not a module" error`), and **3 carry _no_ comment marker at all** — a bare `export {};` with no `@generated` line (`packages/manifest-generation/src/domain/index.ts`, `packages/manifest-generation/src/infrastructure/index.ts`, `packages/wizard-orchestration/src/infrastructure/index.ts`). Those three are marker-less; ADR-0026 treats a marker-less barrel as hand-written (see Decision 5), which is why the "stop emitting" rule must be careful about them.

AGENTS.md rule 7 (`AGENTS.md:143`) states: "Never leave a barrel with only `export {}`." But this is not undocumented drift — **ADR-0007 explicitly decided it.** ADR-0007's Implementation section reads: "Fixed recursive barrel generator to use `export {};` for empty layer directories (not comment-only)" (`ADR-0007-barrel-generation-consolidation.md:110`), and its "Barrel Generation After Fix" diagram (heading at line 126, code block at lines 128-146) shows every layer folder carrying an `index.ts`. That convention is still live in the emitter: `packages/sync/src/generators/barrels/recursive.ts:293-336` keeps or creates `${GENERATED_MARKER}\n\nexport {};\n` for any `domain`/`application`/`infrastructure` layer directory (the `isLayerDir` branches at lines 310-336) and only deletes empty barrels in _non_-layer directories (lines 303-309). So AGENTS.md and ADR-0007 directly conflict, and C4 as drafted (`docs/planning/2026-08-13-architecture-review/ADR-CANDIDATES.md:105-131`) ignored the ADR-0007 decision entirely (audit correction, `docs/planning/2026-08-13-architecture-review/AUDIT-2026-08-14.md:72,264-266`). This ADR resolves that conflict.

### 2. Two frozen contexts are pure scaffolds with zero runtime code

`architectural-enforcement` and `code-generation` are declared `status: frozen` in `.architecture/manifest.yaml:112-123` (both `frozen_since: '2026-05-12'`), and their entire `src/` tree is barrels: each has exactly four files — `src/index.ts` (a wildcard re-export) plus three empty `export {};` layer barrels (`domain/`, `application/`, `infrastructure/`) — no entities, no ports, no adapters. They are still referenced from `tsconfig.base.json:21-22`. Their `EchoFakePort`-only suites are the sole tests in those packages (part of AUD-018, `docs/planning/2026-08-13-architecture-review/AUDIT-2026-08-14.md:227-232`).

Not every frozen context is empty: `transaction-system` is also `status: frozen` (`.architecture/manifest.yaml:159-164`) **but is fully implemented** — 38 source files including real use-cases, ports, adapters, and value objects (`packages/transaction-system/src/application/use-cases/`, `.../infrastructure/adapters/`). It must not be deleted. "Frozen" alone is not a deletion signal; "frozen **and** no runtime code" is.

### 3. `core-domain` and `runtime` have real code outside their hexagonal layers

`core-domain` re-exports its Minimal Viable Kernel from `src/index.ts` (`export * from "./mvk/v1/index.js"`, `packages/core-domain/src/index.ts:1`) — 13 real modules under `src/mvk/v1/` — while its `domain/`, `application/`, and `infrastructure/` barrels are empty `export {};` (HEX-025). `runtime` is the same shape: real guard modules re-exported at the `src/` root (`packages/runtime/src/index.ts` re-exports from `./node-kind-guards.js`, `./edge-kind-guards.js`, `./intent-lineage-runtime.js`, `./topology-invariant-guards.js`, `./cardinality-invariant-guards.js`) with three empty layer barrels. The code is real; the hexagonal layer folders are vestigial.

### 4. The arch-linter tsconfig NodeNext outlier (HEX-035 residue)

The review missed that `tools/arch-linter/tsconfig.json:4-5` uses `"module": "NodeNext"` / `"moduleResolution": "NodeNext"` while `tsconfig.base.json:9` is `"moduleResolution": "bundler"` (`docs/planning/2026-08-13-architecture-review/AUDIT-2026-08-14.md:82`). Note that `tsconfig.base.json` does **not** reference `tools/arch-linter` (its `references` array covers `packages/*` only), so this reconciliation is a standalone alignment of the arch-linter config, not a base-references edit. It is adjacent to the empty-folder cleanup and is reconciled here so the `tsconfig.base.json` references item and the arch-linter outlier land in one place.

## Decision

### 1. Retire the `export {};` empty-layer-barrel convention

**Supersede ADR-0007's Implementation decision** that empty layer directories carry an `export {};` barrel. The generator SHOULD emit a layer barrel only when the context YAML declares content (entities/ports/adapters) for that layer — i.e. the barrel is created when `walkDirectory` produces exportable content, and empty layer directories are not scaffolded with a placeholder module. ADR-0007's _single-walker_ rule (one owner: `packages/sync/src/generators/barrels/recursive.ts`) is **unchanged and reaffirmed** — this ADR narrows only which barrels that single walker emits, not who emits them. The `layer-folders.ts` generator's consolidation into that single walker (`packages/sync/src/generators/layer-folders.ts:183-188`, with `sync-engine.ts:133-135` recording that barrels are single-owned by the recursive pass) is likewise preserved.

AGENTS.md rule 7 becomes the enforced convention rather than an aspiration in tension with ADR-0007.

### 2. Delete frozen no-code scaffolds; keep implemented frozen contexts

`architectural-enforcement` and `code-generation` are removed from `packages/`, from `bounded_contexts` in `.architecture/manifest.yaml` (the top-level key at `.architecture/manifest.yaml:36`), and from `tsconfig.base.json` references — deleting their `EchoFakePort`-only suites with them. **`transaction-system` is explicitly retained** (frozen but implemented, 38 files). The deletion predicate is "frozen AND no runtime code," proven per-package by the scout's zero-consumers check, never "frozen" alone.

### 3. `core-domain` and `runtime` re-export their real modules through the hexagonal layers, or drop the vestigial folders

For `core-domain` and `runtime`, the real code stays; the empty layer barrels are corrected — either by relocating the real modules under the appropriate `domain/` layer and re-exporting, or by removing the vestigial empty layer folders where the flat `src/` layout is the intended shape. The choice per package is left to the implementing PR (Wave 6, item 6.7(c)); this ADR only decides that an empty `export {};` layer barrel next to real out-of-layer code is not an acceptable end state.

### 4. Reconcile `tsconfig.base.json` references, including the arch-linter NodeNext outlier

After the deletions in Decision 2, `tsconfig.base.json:21-22` references are removed. The `tools/arch-linter/tsconfig.json:4-5` NodeNext/bundler outlier is aligned in the same reconciliation pass (Wave 6, item 6.7(d)). Because `tsconfig.base.json` does not currently reference the arch-linter, aligning it is a change to the arch-linter's own config, not to the base references list.

### 5. Coordinate with ADR-0026 — do not weaken hand-written preservation

None of the above overrides ADR-0026. The generator changes in Decision 1 alter what the _recursive barrel generator_ emits into `@generated` layer barrels; they do not touch `safeWriteFileAtomic`'s hand-written protection, the three flag tiers (`ADR-0026-...md:66-74`: none/`--force` preserve hand-written; only `--force-root` overwrites), or the `protectedFiles` list. A hand-written barrel — one _without_ the `@generated` marker — is still preserved untouched. This has a concrete edge in the current tree: the 3 marker-less bare `export {};` barrels (Context §1) are, under ADR-0026, indistinguishable from hand-written files, so `yarn sync` will not remove them; the implementing PR (6.7) must delete those 3 explicitly (or add the `@generated` marker so the emitter owns them) rather than expecting the "stop emitting" rule to clear them. The class of barrels the rule cleanly owns is those carrying `// @generated by @hexagen/sync` — exactly the class ADR-0026 already treats as generator-owned (`ADR-0026-...md:93`). The single-walker-respects-hand-written-customisation guarantee ADR-0026 records for barrels (`ADR-0026-...md:142`: "the single walker must respect hand-written barrel customisations, not overwrite them") is preserved verbatim.

## Consequences

- **AGENTS.md rule 7 and ADR-0007 stop contradicting each other.** The `export {};` convention is retired at the source (`recursive.ts:310-336`) rather than left as a documented-but-violated rule; ADR-0007's single-walker and `src/`-only-barrels decisions remain in force.
- **Generated projects inherit the corrected emitter.** Because the change is in `@hexagen/sync`'s recursive barrel generator, every downstream project scaffolded after the next npm release stops receiving empty placeholder layer barrels — this is a published-package behavior change and is release-gated (per the plan's release-gated-items policy).
- **`transaction-system` survives; the deletion sweep is content-gated, not status-gated.** The "frozen AND no code" predicate prevents a future sweep from mistaking an implemented frozen context for a dead scaffold.
- **Two packages leave the monorepo.** `architectural-enforcement` and `code-generation` deletion removes their `tsconfig.base.json` references and their `EchoFakePort`-only suites, shrinking the AUD-018 mock-test surface (coordinated with plan item 6.7(b) / 8.10).
- **The 3 marker-less barrels need explicit handling.** Because they carry no `@generated` marker, ADR-0026 will preserve them across `yarn sync`; 6.7 must delete them by hand (or mark them generated) so the corrected end state is actually reached.
- **The linter must tolerate opted-out layers.** After Decision 1, the arch-linter must not require a `domain/` (or other) layer folder on a context or shared-kernel that legitimately has none (e.g. the flat `core-domain`/`runtime` shape) — the enforcement-posture ADR (0.8) and its layer-rules changes carry this so the ratchet does not re-flag the corrected state.
- **No regression in hand-written safety.** Because Decision 5 leaves ADR-0026's guarantees intact, a user who hand-authors a non-`@generated` barrel keeps it across `yarn sync` and `yarn sync --force`.
- **Implementation is Wave 6, item 6.7(a)–(d)** of `docs/planning/2026-08-14-architecture-remediation-plan.md` (row at line 288; Wave-0 slot 0.4 at line 138); this ADR is a decision input only. Human acceptance is via PR merge (Status: Proposed).

## Amendment — 2026-08-17: Decision 4's "single NodeNext outlier" premise is withdrawn

Decision 4 treated `tools/arch-linter/tsconfig.json` as the one NodeNext hold-out against a bundler-resolved `tsconfig.base.json`, and scheduled an alignment of that file to bundler as part of 6.7(d).

That premise is false on the tree. The workspaces Node executes directly are:

| Workspace                  | Config                             | Resolution                                                                                                       |
| -------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `@hexagen/sync` **source** | `packages/sync/tsconfig.json`      | `bundler` + `module: Preserve` — **ADR-0009 / AGENTS.md**. tsup emits the published ESM; source is not NodeNext. |
| `@hexagen/sync` **tests**  | `packages/sync/tsconfig.test.json` | `NodeNext`                                                                                                       |
| `@hexagen/tui`             | `apps/tui/tsconfig.json`           | `NodeNext`                                                                                                       |
| `@hexagen/arch-linter`     | `tools/arch-linter/tsconfig.json`  | `NodeNext`                                                                                                       |

6.7(d) (#517) reconciled `tsconfig.base.json` `references` and added the HEX-035 guard. It did **not** flip arch-linter (or tui, or sync tests) to bundler, and that flip is not required: no arch-linter rule demands NodeNext on sync, and accepted ADR-0009 already decided sync _source_ stays bundler.

**Decision 4 is therefore narrowed.** After a package deletion, drop that package's `tsconfig.base.json` reference (the HEX-035 half). Do **not** "align" Node-executed workspaces to bundler. The NodeNext hold-outs above are the documented exceptions, not drift. A later change to tui or arch-linter resolution is its own decision; it is not implied here.

ADR-0009's older problem-statement table that listed `sync (CLI) \| NodeNext` is a leftover of Approach 1 and is footnoted there; Approach 2 and AGENTS.md are the governing text.
