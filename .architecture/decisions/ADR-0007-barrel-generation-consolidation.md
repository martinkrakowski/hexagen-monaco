# ADR-0007: Barrel Generation Consolidation — Deletion of Stub Generator

**Status:** Accepted  
**Date:** 2026-03-13  
**Authors:** Architecture Co-pilot, Human Architect  
**Related PR:** #56

---

## Context

The sync engine had two separate systems generating barrel files (`index.ts`):

1. **Recursive Barrel Generator** (`packages/sync/src/generators/barrels/recursive.ts`)
   - Processes `src/{layer}/` directories recursively
   - Detects circular exports
   - Preserves hand-written barrels
   - Deletes empty barrels (except layer directories)

2. **Stub Generator** (`packages/sync/src/generators/stubs.ts`)
   - Created barrels at package root: `packages/*/domain/`, `packages/*/application/`, `packages/*/infrastructure/`
   - Generated empty stubs with `// No exports yet` comments
   - 100% functionally redundant with recursive generator

### The Problem

The stub generator created package-root-level barrels **outside the TypeScript compilation boundary**:

```
packages/messaging/
├── domain/              ← Created by stub generator (package root)
│   └── index.ts
├── application/         ← Created by stub generator (package root)
│   └── index.ts
└── src/                 ← TypeScript rootDir
    ├── domain/          ← Created by recursive generator
    │   └── index.ts
    └── application/     ← Created by recursive generator
        └── index.ts
```

**Impact:**

- Package-root barrels were empty (`export {}` or comment-only)
- TypeScript encountered them during compilation → **TS2306: File is not a module**
- CI builds failed post-sync
- Two generators competing for the same directories
- Architectural confusion: which barrels are canonical?

### Root Cause

The stub generator was introduced accidentally in commit `c2048e8` (2026-03-08) when the `src/` prefix was omitted from directory paths:

```typescript
// ORIGINAL (correct) — circa 2026-03-05
const stubsDir = path.join(modulePath, 'src', layer, 'stubs');

// MISTAKE — circa 2026-03-08
const stubs = [
  { dir: 'domain', file: 'index.ts', ... },  // Missing 'src/' prefix!
];
```

This was never intentional — the original bootstrap (commit `0084da0`) created barrels **only in `src/`**.

---

## Decision

**Delete the stub generator entirely.** Use only the recursive barrel generator for all barrel creation.

### Rationale

1. **Complete Functional Overlap**
   - Both generators create the exact same barrel files
   - Recursive generator does everything stub generator does, plus:
     - Circular export detection
     - Hand-written barrel preservation
     - Empty barrel cleanup
     - Recursive subdirectory handling

2. **Architectural Alignment**
   - TypeScript compilation boundary is `src/` → `dist/`
   - Package-root barrels exist outside this boundary
   - All source code belongs in `src/`, not at package root

3. **Eliminates Competing Systems**
   - Single source of truth for barrel generation
   - No risk of two generators conflicting
   - Simpler mental model

4. **Fixes CI Failures**
   - No more empty package-root barrels
   - No more TS2306 errors post-sync
   - Consistent behavior across local and CI environments

---

## Implementation

### Changes Made

1. **Deleted `packages/sync/src/generators/stubs.ts`** (~70 lines)
2. **Removed stub generator call** from `sync-engine.ts`:
   ```diff
   - const stubResult = await generateStubs(moduleDir, config, this.report);
   ```
3. **Removed stub reporting** from sync summary
4. **Deleted 81 package-root-level barrels** across all packages
5. **Fixed recursive barrel generator** to use `export {};` for empty layer directories (not comment-only)

### Files Deleted

Package-root barrels removed:

- `packages/*/domain/index.ts` (10 files)
- `packages/*/application/index.ts` (10 files)
- `packages/*/application/ports/in/index.ts` (10 files)
- `packages/*/application/ports/out/index.ts` (10 files)
- `packages/*/application/use-cases/index.ts` (10 files)
- `packages/*/infrastructure/index.ts` (10 files)
- `packages/*/infrastructure/adapters/index.ts` (10 files)

**Total:** 81 files deleted

### Barrel Generation After Fix

```
packages/messaging/
└── src/                              ← All barrels now in src/
    ├── domain/
    │   └── index.ts                  ← Generated by recursive generator
    ├── application/
    │   ├── ports/
    │   │   ├── in/index.ts
    │   │   └── out/index.ts
    │   ├── use-cases/index.ts
    │   └── index.ts
    └── infrastructure/
        ├── adapters/index.ts
        └── index.ts
```

## Consequences

### Positive

- ✅ **CI builds pass** — no more TS2306 errors
- ✅ **Single source of truth** — only recursive generator creates barrels
- ✅ **Architectural clarity** — all barrels in `src/`, all output in `dist/`
- ✅ **Simpler codebase** — 70 lines of redundant code deleted
- ✅ **Prevents future bugs** — no risk of generator conflicts
- ✅ **Aligns with TypeScript composite projects** — respects `rootDir: "src"`

### Negative

- ⚠️ **Breaking change for manual workflows** — any scripts expecting package-root barrels will break (unlikely, as these were never intentional)

### Neutral

- Sync output no longer shows "Stubs" line in summary
- Barrel generation count now reflects only recursive generator operations

## Alternatives Considered

### Option A: Move Stub Generation to `src/`

Change stub paths from `domain/` to `src/domain/`.

**Rejected because:**

- Still maintains redundant generator
- Risk of future conflicts between generators
- More code to maintain

### Option B: Skip Empty Stubs

Add conditional logic to only create stubs if directory has content.

**Rejected because:**

- Adds complexity
- Doesn't address fundamental redundancy
- Two generators still exist

### Option C: Delete Stub Generator (CHOSEN)

Remove stub generator entirely; use only recursive generator.

**Chosen because:**

- Eliminates root cause
- Simplifies architecture
- Single source of truth
- No functional loss

## Notes

This ADR resolves a three-week-old issue where package-root barrels caused intermittent CI failures. The root cause was traced through git archaeology to an accidental omission of the `src/` prefix during a refactor.

The fix demonstrates the value of:

- Deleting redundant systems rather than patching them
- Following the compilation boundary (`src/` → `dist/`)
- Single source of truth for code generation
