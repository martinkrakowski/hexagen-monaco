# Generic-token review
#
# Every line is one token that appears in `generic/`, also appears somewhere in the pinned
# `source/` snapshot, and appears in **no** tracked hexagen file outside
# `packages/template-engine/__tests__/fixtures/orchestration/` and `docs/planning/`. A
# hand-written list of campaign-foundry's own strings cannot catch everything, so this is the
# mechanical sweep behind it: the test recomputes the same set and fails on anything missing here.
#
# The token is the RAW text of an inline code span (one surrounding space stripped), or one
# whitespace-separated word of a fenced block, in `SKILL.md` or `references/rationale.md`. Nothing
# is collapsed: internal whitespace, including a line break, is part of the token, and the test
# looks for it as-is in the pinned `source/` and in the tracked hexagen files. A review file holds
# one line per token, so an internal newline is written here as the two characters \n (and a literal
# backslash as \\) and unescaped when the file is loaded.
#
# Format: <token><TAB><why the token is generic>. Every line below is reviewed by hand — the
# test can only check that a reason is present and non-empty, never that it is right. A reason
# that is not worth reading is a leak that got through, so each one says what the token is and
# why it is not a campaign-foundry fact.
