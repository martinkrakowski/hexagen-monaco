# TESTING.md — HexaGen Testing Protocol

Referenced by Develop Mode and the Test/QA Worker sub-agent.

---

## File Layout

```
packages/<name>/
├── src/                          # production code only
│   └── infrastructure/
│       └── adapters/
│           └── yaml-config.adapter.ts
└── __tests__/                    # mirrors src/ structure
    ├── doubles/                  # test doubles live here
    └── infrastructure/
        └── adapters/
            └── yaml-config.adapter.test.ts
```

---

## Result Type Convention

```ts
type Result<T, E = Error> =
  | { success: true; value: T }
  | { success: false; error: E };
```

Every catch block must return `Result<T, E>`. Returning `null`, `false`, or a default
value is a hard rejection.

---

## Every Develop Slice Must Produce

1. The adapter
2. A test double in `__tests__/doubles/` implementing the exact same interface
3. Unit tests covering: happy path · error case · at least one edge case

---

## Test Double Parity Rule

Test doubles must implement **exactly** the same TypeScript interface as the real adapter —
no extra methods, no missing methods. Verified by `yarn typecheck`.

---

## Package.json Standards

```json
{
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  }
}
```

---

## Sync Engine Rules (`packages/sync/`)

- All generators return `Result<GeneratorResult, Error>`
- NodeNext module resolution — explicit `.js` extensions required on all imports
- Barrel files carry the `// @generated by @hexagen/sync` marker
