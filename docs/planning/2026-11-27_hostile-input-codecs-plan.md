# Plan: typed port contracts and generated codecs (hostile input at the boundary, hexagen side)

- **Date:** 2026-11-27
- **Status:** rev 0 draft
- **Companion:** `fleet-v2/docs/planning/2026-11-27_hostile-input-at-boundary-plan.md` (units HIB1–HIB5 plus backlog)
- **Owner decisions (2026-11-27):**
  - Accepted the five recommendations D1–D5 reproduced in Section 6.
  - Contract ownership stays with `hexagen-monaco` per the 2026-10-25 integration decision ([consumer-contract-and-fleet-integration.md](../../docs/planning/consumer-contract-and-fleet-integration.md)), and `fleet-v2` consumes only exact-pinned published releases.

## 1. Goal and non-goals

**Problem:** Hand-rolled hostile-input handling is spread through the `fleet-v2` codebase (about 563 `getOwnPropertyDescriptor` calls in 187 files, about 75 private `isPlainObject`/`isPlainRecord`/`isRecord` copies, 53 of 97 use cases taking `unknown`), and about 24 lanes are blocked on it. These figures come from the fleet-v2 survey of 2026-11-27 and are order-of-magnitude (the companion plan notes the use-case count differs from a re-count). Fleet Cloud clients may bring other models, so correctness must not depend on model diligence.

**Goal:** Extend `hexagen-monaco` so that:
1. Bounded-context manifests can declare typed `contracts:` blocks on ports (fields, types, bounds, exactness, optionality, nesting) plus a configurable `codec.runtimeModule` (default `@fleet/shared`).
2. `hexagen sync` deterministically emits per-port `<PortName>.codec.ts` modules (with a branded `<PortName>Request` type and `create<PortName>Codec(env)` factory) and per-codec `<PortName>.codec.test.ts` adversarial test suites targeting the `fleet-v2` runtime kernel API.
3. Generated codecs and tests carry `// @generated by @hexagen/sync`, are never hand-edited, and are enforced by `hexagen sync --check` drift detection.
4. `hexagen-lint` (`@hexagen/arch-linter`) enforces "no in-port accepts `unknown`" (warn/ratchet first, then ratchet down) so unmigrated ports cannot silently re-introduce untyped boundaries.

**Non-goals:**
- Implementing `snapshotPlainData`, `createCodec`, `ADVERSARIAL_CORPUS`, or `runAdversarialCorpus` in `hexagen-monaco` (those live in `fleet-v2` units HIB1–HIB2).
- Adding any npm runtime dependency (e.g., `zod`) to generated domain or application code (ADR-0054).
- Migrating `fleet-v2` use cases, deleting `fleet-v2` per-use-case Proxy tests, or auto-merging `fleet-v2` PRs (handled in `fleet-v2` after the H5 release hand-off).
- Changing `hexagen`'s CLI binary contract (ADR-0056).

## 2. What exists today (verified)

- **Manifest port declarations:**
  - [layers.ts](../../packages/sync/src/types/manifest/layers.ts) defines `PortDefinition` (`{ name: string; owner?: string }`) and `LegacyOrNewPort = string | PortDefinition` under `ApplicationPorts.in` and `ApplicationPorts.out`.
  - [manifest-schema.ts](../../packages/project-configuration/src/domain/model/manifest-schema/manifest-schema.ts) defines `PortDefinitionSchema` (`name`, `owner?`) and `LegacyOrNewPortSchema` (`z.union([z.string(), PortDefinitionSchema])`), used by both `validateManifest` in [sync-engine-init.ts](../../packages/sync/src/sync-engine-init.ts) and `mergeSplitManifest` in [cli.ts](../../tools/arch-linter/src/cli.ts).
  - [generator.ts](../../packages/sync/src/types/manifest/generator.ts) defines `SyncConfig` and `GeneratorConfig` (`name`, `version`, `sync`), with no `codec` configuration yet.
  - [port.ts](../../packages/sync/src/commands/arch/port.ts) and [persistence.ts](../../packages/sync/src/commands/arch/port/persistence.ts) scaffold string-only port entries into `.architecture/manifest.yaml`.
- **Stub & file generation and drift gate:**
  - [sync-engine.ts](../../packages/sync/src/sync-engine.ts) runs `generateBarrels`, `generatePackageJson`, `generateTsconfig`, `ensurePackageSrcIndex`, `generateEslintConfig`, and `generateStubs` per bounded context, plus `generateSharedKernel` ([shared-kernel.ts](../../packages/sync/src/generators/shared-kernel.ts)).
  - [stubs.ts](../../packages/sync/src/generators/stubs.ts) and [emission-plan-builder.ts](../../packages/sync/src/domain/services/emission-plan-builder.ts) resolve layer directories via `resolveEmissionDir` ([layer-dir-resolver.ts](../../packages/sync/src/domain/services/layer-dir-resolver.ts)) and preserve existing stubs once written (write-if-absent).
  - [port-analyzer.ts](../../packages/sync/src/generators/port-analyzer.ts) parses port interfaces with `ts-morph` to scaffold adapters and use cases.
  - [fs-utils.ts](../../packages/sync/src/fs-utils.ts) (`safeWriteFileAtomic`, `isGeneratedFile`) overwrites files carrying `// @generated by @hexagen/sync` (as [eslint.ts](../../packages/sync/src/generators/eslint.ts) does) and reports `created` / `updated` / `unchanged` under `hexagen sync --dry-run` / `hexagen sync --check` ([cli.ts](../../packages/sync/src/cli.ts)).
- **Arch-linter & ratchet:**
  - [cli.ts](../../tools/arch-linter/src/cli.ts) loads the merged manifest and `ts-morph` `Project`, runs layer-purity checks ([layer-purity-violation.ts](../../tools/arch-linter/src/layer-purity-violation.ts)), partitions findings against `.architecture/arch-lint-baseline.json` via [ratchet-baseline.ts](../../tools/arch-linter/src/ratchet-baseline.ts), and exits `0` (compliant), `1` (fresh/expired/growing violations), or `2` (could not run). [validate.ts](../../packages/sync/src/commands/arch/validate.ts) wraps `hexagen-lint --json`.
- **Working rules & test stack:**
  - [AGENTS.md](../../AGENTS.md) and [TESTING.md](../../.agents/TESTING.md) mandate Vitest (`vitest run`), `yarn build && yarn typecheck && yarn lint` before/after edits, and never hand-editing generated files.

## 3. Shape

```
.architecture/manifest.yaml (port contracts: + generator.sync.codec.runtimeModule)
        │
        ├─► [H1] ManifestSchema + PortDefinition types (additive; legacy ports still valid)
        │
        ├─► [H2] SyncEngine → generateCodecs()
        │         ├─ resolves port dir via resolveEmissionDir(layers, "application/ports/in")
        │         └─ emits <PortName>.codec.ts (// @generated by @hexagen/sync)
        │              imports { createCodec, CodecSchema, CodecEnv, Validated, DecodeResult }
        │              from codec.runtimeModule (default "@fleet/shared")
        │              exports <PortName>Request (branded) + create<PortName>Codec(env)
        │
        ├─► [H3] SyncEngine → generateCodecTests()
        │         └─ emits <PortName>.codec.test.ts (// @generated by @hexagen/sync)
        │              Vitest describe.each(ADVERSARIAL_CORPUS) + valid-sample round trip
        │
        └─► [H4] hexagen-lint (tools/arch-linter) + hexagen sync --check
                  ├─ new rule: in-port-unknown (flags in-ports accepting `unknown`, warn/ratchet)
                  └─ sync --check detects any drift on *.codec.ts and *.codec.test.ts
```

**Architecture invariant:** Decode **once** per boundary. Composition roots (`apps/cli`, `apps/api`, `apps/mcp` in `fleet-v2`) and outbound adapters decode with a generated codec. Ports carry only `Validated<T>` (deep-frozen, null-prototype, branded, constructible only by the codec). Use cases take `Validated<Request>`, never `unknown`. Domain and application code never reflect on input.

## 4. Cross-repo interface

> **Authority notice:** The runtime API contract below is **DEFINED** in `fleet-v2/docs/planning/2026-11-27_hostile-input-at-boundary-plan.md` (units HIB1–HIB2). This plan only references and targets it. The Hexagen emitter (H2–H3) must be updated if that contract changes.

```text
Module `@fleet/shared` (the runtime module specifier is configurable in the manifest as `codec.runtimeModule`, default `@fleet/shared`) exports exactly:
- `type Validated<T>`: T made deeply readonly and branded (`{ readonly [validatedBrand]: true }` with a non-exported unique symbol), so only the codec can construct it.
- `type CodecSchema`: a plain-data schema literal: `{ kind: 'object'; exact: true; fields: Record<string, CodecSchema | { optional: CodecSchema }> }` | `{ kind: 'array'; items: CodecSchema; maxItems: number }` | `{ kind: 'string'; maxLength: number; pattern?: string }` | `{ kind: 'integer'|'number'; min?: number; max?: number }` | `{ kind: 'boolean' }` | `{ kind: 'enum'; values: readonly string[] }` | `{ kind: 'literal'; value: string|number|boolean|null }` | `{ kind: 'nullable'; of: CodecSchema }`. Every string and array carries an explicit bound; every object is exact (unknown keys refused) and reserved keys are always refused.
- `type CodecEnv = { readonly isProxy: (value: unknown) => boolean }` and `type Codec<T> = { readonly schemaId: string; decode(input: unknown): DecodeResult<T> }`.
- `type DecodeResult<T> = { ok: true; value: Validated<T> } | { ok: false; reason: DecodeRefusalReason; path: string | null }` where `DecodeRefusalReason` is the union of PlainDataRefusalReason (existing kernel reasons) plus 'wrong-type' | 'missing-key' | 'unknown-key' | 'reserved-key' | 'out-of-bounds' | 'pattern-mismatch' | 'not-in-enum'. No refusal ever echoes input values.
- `function createCodec<T>(schemaId: string, schema: CodecSchema, env: CodecEnv): Codec<T>`: snapshots through `snapshotPlainData(input, env.isProxy)` first, then validates the frozen snapshot against the schema, then returns a null-prototype deep-frozen branded value. A thrown error is never an outcome: it becomes a typed refusal.
- `const ADVERSARIAL_CORPUS: readonly { id: string; category: string; build(): unknown }[]` (in packages/shared/src/adversarial-corpus.ts): hostile values built at run time (Proxy, revoked Proxy, getter, setter, cycle, __proto__ and constructor keys, symbol keys, sparse array, array-like, over-deep nesting, over-wide object, over-long string, huge array length, NaN, Infinity, negative zero, non-plain prototype, class instance, function value). Every entry must be refused by every codec.
- `function runAdversarialCorpus(codec: Codec<unknown>, env: CodecEnv): readonly { id: string; refused: boolean }[]` for generated tests (`describe.each(ADVERSARIAL_CORPUS)`).
Bounds default to the kernel's DEFAULT_PLAIN_DATA_LIMITS. Generated code (per port: `<PortName>.codec.ts` exporting `<PortName>Request` branded type and `create<PortName>Codec(env)`) imports only from the runtime module, never from npm.
```

## 6. Decisions

- **D1 — Threat split** *(ACCEPTED, owner, 2026-11-27)*: Proxy/accessor refusal only at in-process boundaries, through the existing kernel `snapshotPlainData(value, isProxy, limits?)` in `fleet-v2/packages/shared/src/plain-data-snapshot.ts` (the injected `isProxy` runs first; it refuses accessors, cycles, bounds; deep-freezes; returns `{ok:true,value}|{ok:false,reason,path}`). `types.isProxy` is bound ONCE in infrastructure. JSON-origin data (files, HTTP bodies, subprocess output) needs schema, bounds, exact keys, and reserved-key (`__proto__`, `constructor`, `prototype`) refusal only, not Proxy detection.
- **D2 — Codec engine** *(ACCEPTED, owner, 2026-11-27)*: Extend the in-house `fleet-v2/packages/shared/src/plain-record.ts` (`readPlainRecord`, `PlainRecordSchema`, `MAX_SCHEMA_FIELDS=64`, `MAX_DEPTH=8`) into one schema layer over the kernel. No npm runtime dependency in domain/generated code (ADR-0054). It folds `readPlainRecord`, `readExactPlainRecord` / `readPlainRecordWithOptionalKeys` / `snapshotPlainDataRecord` / `readBoundedDenseArray` (`fleet-v2/packages/work-execution/src/domain/plain-record-reads.ts`), and `readPlainObject` / `readPlainObjectWithOptional` (`fleet-v2/packages/operator-coordination/src/domain/record-input.ts`).
- **D3 — Schema source** *(ACCEPTED, owner, 2026-11-27)*: The manifest's port `contracts:` block; Hexagen generates codecs, branded types, and tests. Fallback: hand-written `*.codec.ts` files, enforced by `lint:arch`.
- **D4 — Freeze new hand-rolled validation now** *(ACCEPTED, owner, 2026-11-27)*: An ESLint `no-restricted-syntax` ban in domain/application for `getOwnPropertyDescriptor`, `Reflect.ownKeys`, `getPrototypeOf`, `Proxy`, `structuredClone`, `JSON.parse`, plus a count ratchet file that fails CI on any increase (warn-only first), plus a `lint:arch` rule "no in-port accepts `unknown`".
- **D5 — Test retirement cadence** *(ACCEPTED, owner, 2026-11-27)*: Delete per-use-case Proxy/hostile tests as each use case migrates, not upfront.
- **D6 — Codec emission mode** *(RECOMMENDED, not yet accepted)*: Emit `<PortName>.codec.ts` and `<PortName>.codec.test.ts` only for ports that declare `contracts:`, using `// @generated by @hexagen/sync` so `hexagen sync` always overwrites them and `hexagen sync --check` catches any drift or hand-edit. Ports without `contracts:` rely on the D3 fallback (`*.codec.ts` hand-written) until migrated.
- **D7 — `in-port-unknown` enforcement rollout** *(RECOMMENDED, not yet accepted)*: Ship `in-port-unknown` in `tools/arch-linter` as a baselined/warn-first rule in H4 so existing repos do not red-wall on upgrade; teams burn down `.architecture/arch-lint-baseline.json` per ADR-0054 as ports migrate.

## 7. Risks

- **Cross-repo contract drift:** H2 and H3 target the HIB1–HIB2 runtime API before `fleet-v2` HIB2 lands. Any signature change in `@fleet/shared` (`createCodec`, `CodecSchema`, `ADVERSARIAL_CORPUS`, `runAdversarialCorpus`) invalidates generated files until H2/H3 are updated and re-released.
- **Manifest schema strictness vs. passthrough:** `BoundedContextSchema` in [manifest-schema.ts](../../packages/project-configuration/src/domain/model/manifest-schema/manifest-schema.ts) uses `.passthrough()` for forward compatibility, while `PortDefinitionSchema` must validate `contracts:` strictly enough to reject unbounded strings/arrays or non-exact objects at sync time without breaking legacy string ports.
- **Barrel re-exports:** `generateBarrels` in [sync-engine.ts](../../packages/sync/src/sync-engine.ts) indexes `src/` files; generated `<PortName>.codec.test.ts` must either live under `__tests__/` or be excluded from production barrel exports (matching `countsAsContextExportSource` in [cli.ts](../../tools/arch-linter/src/cli.ts)) so test files are not bundled into `dist/`.
- **Stale `dist` in local worktrees:** Both `@hexagen/sync` and `@hexagen/arch-linter` consume `@hexagen/project-configuration` and `@hexagen/shared`; forgetting `yarn build` after H1 will cause H2/H4 to read stale `.d.ts` types.

## 8. Order

1. **H1** — Manifest schema extension and loader validation (`contracts:` + `codec.runtimeModule`).
2. **H2** — Codec emitter (`<PortName>.codec.ts` + `<PortName>Request` + `create<PortName>Codec`), targeting the HIB2 contract text in Section 4.
3. **H3** and **H4** in parallel — Generated adversarial tests (`<PortName>.codec.test.ts`) and `lint:arch` `in-port-unknown` rule + `sync --check` drift contract tests.
4. **H5** — Exact-pinned release of `@hexagen/sync` and `@hexagen/arch-linter`, plus `fleet-v2` hand-off PR (unblocks `fleet-v2` pilot unit `HIB4`).

## Hard to undo

- **Manifest `contracts:` YAML shape (H1):** Once provisioned projects commit `.architecture/manifest.yaml` entries using `contracts:`, renaming keys (`fields`, `maxLength`, `maxItems`, `optional`, `nullable`) requires a manifest migration command (`hexagen manifest migrate`) and a deprecation window per [consumer-contract-and-fleet-integration.md](../../docs/planning/consumer-contract-and-fleet-integration.md).
- **Generated codec file naming and exports (H2):** `<PortName>.codec.ts`, `<PortName>Request`, and `create<PortName>Codec(env)` become imported symbols in `fleet-v2` composition roots and use cases; changing the naming convention later breaks every consumer import.
- **Linter rule ID `in-port-unknown` (H4):** Baseline keys in `.architecture/arch-lint-baseline.json` embed the rule ID ([ratchet-baseline.ts](../../tools/arch-linter/src/ratchet-baseline.ts)); renaming it invalidates committed baselines.

## Assumptions

- `fleet-v2` units HIB1–HIB2 export the exact symbols and types listed in Section 4 from the configured `codec.runtimeModule` (default `@fleet/shared`), and `CodecEnv.isProxy` is supplied by infrastructure at composition roots.
- Every `string` and `array` field in a port `contracts:` block either specifies an explicit bound (`maxLength` / `maxItems`) or is rejected by H1 validation rather than silently emitting unbounded schemas.
- `hexagen-monaco` releases `@hexagen/sync` and `@hexagen/arch-linter` at exact-pinned versions consumable by `fleet-v2` without workspace-link overrides.

## Challenge this

- **Should `contracts:` support outbound ports too, or only inbound ports?** H4 specifically checks "no in-port accepts `unknown`", whereas H2 mentions per-port codecs and the architecture states composition roots *and outbound adapters* decode with a codec. Confirm whether `application.ports.out` `contracts:` should emit into `application/ports/out` in H2 or wait for a follow-up.
- **Where should `<PortName>.codec.test.ts` live?** Co-locating next to `<PortName>.codec.ts` in `application/ports/in/` keeps the test beside the generated codec, but requires `tsconfig.build.json` and barrel generation to exclude `*.test.ts`. Placing it under `__tests__/application/ports/in/` matches [TESTING.md](../../.agents/TESTING.md) and avoids barrel/build exclusions.
- **Valid-sample synthesis for `pattern` strings (H3):** Generating a deterministic valid sample from an arbitrary `pattern?: string` regex in H3 is non-trivial without a regex-inverter dependency (which ADR-0054 discourages in domain). Either require an explicit `example` on `pattern` fields in H1 or restrict `pattern` to a small supported subset / provide a sample override.
