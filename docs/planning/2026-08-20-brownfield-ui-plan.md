# Brownfield UI plan — import, ratify, install the gate

**Date:** 2026-08-20 · **Status:** decision-ready; adversarially verified against the tree (all named components/contracts confirmed to exist; six defects found and folded in, then a second adversarial round: 3 findings accepted with corrections, 2 refuted — see §7)
**Baseline:** `origin/main` @ `4dddf1e1`. Both packages published at **0.11.0** on npm (2026-08-18); `hexagen scan` ships in the next release.
**Doctrine (binding):** ratification, not auto-detection — the tool proposes, the user confirms. No confidence theater (the contracts genuinely carry no confidence scores). Deterministic and honest.

## 1. Entry points

1. **GitHub repo URL (primary).** Mounts at `/projects/new/import/github` — the sub-option already exists as `coming-soon` in `IMPORT_SUB_OPTIONS` (`features/landing/domain/creation-path.ts`). Sub-paths:
   - **Public repo, anonymous** — paste URL + branch; server shallow-clones, scans, discards. Zero-friction demo path. **Bounding the clone (corrected in review round 2):** `--filter=blob:limit` only drops _large_ blobs — a repo of millions of 1 KB blobs sails through it, and a mid-clone `du` poll is racy on NVMe. Bound it deterministically instead: (i) pre-flight `GET /repos/{owner}/{repo}` and reject on the API's `size` field above a cap before any bytes move; (ii) clone into a **size-capped tmpfs mount** (OS-enforced, not polled) with `--depth 1 --single-branch`; (iii) hard wall-clock kill on the child process. `du` polling is belt-and-braces only. Needs a **quota gate** — anon `hxg_sid` daily cap **plus** the per-IP `checkRateLimit` backstop (`lib/rate-limiter.ts`; `anon-session.ts` already documents that the cookie alone is trivially re-minted) — not just the 5/min `guardMutation` limit. A free arbitrary-repo clone endpoint is an abuse magnet.
   - **Private repo, signed-in** — OAuth `repo` scope already granted (`auth.ts:25`), server-held token clones. Tier B rules apply.
   - **GitHub App (future, do not build now)** — installation tokens, org repo pickers, webhook re-scans. Blocked on org tenancy (hosting plan H1); it is also the only procurement-viable automated-PR story (§ S7).
2. **Zip upload** — exists; keep.
3. **CLI-artifact upload (Tier A)** — new screen accepting the handoff zip or loose `manifest.yaml`/`layout.yaml`/`arch-lint-baseline.json`/report. Server parses files in-process; **no CLI execution server-side → immune to the D-P1 image blocker. Build first.** The handoff zip is four small files, so API-1 gets its **own tight limit profile** (single-digit entry cap, low per-entry/total byte caps) rather than inheriting the 256 MiB scan profile — see API-1 and the unpacker note in §4.
4. **PR-comment deep link** — `post-comment.mjs` gains a "Review in Hexagen-Monaco" link (`?repo=&pr=` prefill). XS cost, and it is the **only organic acquisition loop** in the product — promoted into the MVP.
5. **CI artifact re-upload** (later) — the conformance action optionally uploads the handoff zip as a workflow artifact with an import link; variant of (3).

**Do not build:** GitLab/Bitbucket (no OAuth machinery; audience is GitHub-centric) · in-browser clone via isomorphic-git (CORS/auth/size fragility; Tier A already solves the privacy case honestly) · File System Access folder picker (Chromium-only; zip covers it) · VS Code extension (the CLI _is_ the local story) · persistent server-side repo mirrors (ratification is point-in-time; re-scan covers drift).

## 2. Screen-by-screen flow

**S1 — Entry + tier picker.** Repo URL/branch or artifact drop; tier cards stating exactly what leaves the machine; name via the shared `?name=` ProjectNameStep param. _Reuse:_ `ImportSelectionPage` funnel, `ImportOptionRow`, `CreationStepIndicator`/`CREATION_STEPS`. _New:_ `RepoEntryStep`, tier cards.

**S2 — Scan progress (streaming).** NDJSON stages: clone → detect-workspaces → lint → report. Stream clone progress lines as chunks — honest, no fake percentages. _Reuse:_ `useStagedGenerationStream` verbatim (`{endpoint, stageLabels}`; events `stage-start|stage-complete|stage-telemetry`), `AiGeneratingStep`/`ThinkingBlock` visual pattern (both live in `apps/web/features`, i.e. boundary code, not `@hexagen/ui` — DESIGN.md §3.4 `NoSemanticState` does not bind them, and their props are already declarative: `phase`, `stepDetail`, `stageProgress`, `verboseLog`). The new S2 screen follows the same split: the hook holds the stream, the view receives complete props. _New:_ streaming scan route (§4). Fixes the current synchronous-spinner gap.

**S3 — Layout ratification.** `detectWorkspaces` → `DetectedPackage[]` (**no confidence field exists — render as "found," never "87% sure"**). Table: package root → context name (inline rename; duplicates blocked — adopt throws at `detect-workspaces.ts:134`), per-layer directory chips prefilled from the probed aliases, add/remove dirs. Output = `layout.yaml` `contexts`. _Reuse:_ `ChipInput`, `StepHeader`/`WizardFooter`, the `MappingList` pattern. _New:_ `LayoutRatifyStep`.

**S4 — Manifest ratification: the UI _is_ the bootstrap answers collector.** Fields map 1:1 to `BootstrapAnswers` (verified, incl. `stdinJson`, `force`, `skipLayout`): system name, scope (`sanitizeScope` live preview), architecture, per-context include/type/description, and `dependsOn` edges. Bootstrap does not infer edges — the planned `--propose-edges` (strategy feature F7) derives candidates from observed cross-package imports; the UI presents them **unchecked**, ratified one by one. Zero included contexts blocked (bootstrap errors). Final step: diff preview of the exact files to be written + live context map. _Reuse:_ `PeerContextMappingStep` (edges), `BoundedContextStep` patterns, `ReviewStep`'s `Patch[]` add/remove/update UI, `compile-wizard-graph` + `GraphCanvasWrapper`. _New:_ `BootstrapAnswersForm` glue.

**S5 — Findings review + debt-ledger seeding.** Violations grouped by rule. **`BaselineEntry.rule` is an open `string` — group dynamically, never hardcode the list** (a fixed key set would silently drop findings when a rule is added). For reference, the ids the linter emits today are **10**: cross-package-import, domain-layer-import, application-layer-import, cross-layer-relative-import, node-builtin-in-layer, npm-package-in-domain, required-communication, subpath-convention, server-marker-unexpected, server-marker-missing (`tools/arch-linter/src/cli.ts` + `layer-purity-violation.ts`). Per finding: **Baseline it** (reason required; optional `expires` date, calendar-validated) or **Leave fresh**. Sticky honest footer: "N fresh remaining → gate exits 1" / "all baselined → exits 0". Warn on expiry semantics (expired entries fail the gate even if the finding is gone). _Reuse:_ `ValidationFindingsPanel`/`ValidationReportView` patterns, `ScanResultPanel` verdict badge. _New:_ `BaselineSeedingPanel` — **and a prerequisite CLI contract (§4/CLI-1): today no violations array crosses the CLI→web seam** (`ProjectScanResponse` carries only verdict/exitCode/reportMarkdown; `ViolationRecord` never leaves `tools/arch-linter`).

**S6 — Report dashboard.** `EngagementReport`: fresh/baselined/stale/expired counts, `RatchetTrendPoint[]` sparkline, suppression-ledger table, context map (Mermaid short-term via `MermaidDiagramView`; hex canvas via `ContextMapView`/`HexagonalArchitectureView` once manifest→graph mapping is wired), handoff-zip download. _Reuse:_ `PlanWorkbench` slot shell (left: scan history; right: report). _New:_ `ReportDashboard` panels.

**S7 — Install the gate (the leave-behind).** Mode picker (pattern: `PublishSettingsDialog` radio):

- **(a) Download zip — the real close for client engagements.** Ratified `.architecture/{manifest.yaml,layout.yaml,arch-lint-baseline.json}` + vendored conformance action + workflow step, **pinned to npm 0.11.0+** (both packages are published — no SHA-pinning needed). The consultant applies it and opens the PR themselves, inside the client's own review process. Works anonymous, works Tier A.
- **(b) Open PR via OAuth — self-owned repos and demos only.** The `repo` scope is all-repos read/write; client orgs with OAuth-app restrictions (the enterprise default) will reject it, and no consultant should attach a personal grant spanning client repos. Keep behind sign-in with an honest scope warning. The procurement-viable automated PR is the **GitHub App**, deferred with entry point 1c.

_Reuse:_ `ExportDialog` phase machine + degraded-publish warnings, `github-publish-errors.ts` + Reconnect UI, `GithubPublishContext`, `ExportStatusStrip`; gate-file materializer generalized from `sync-integrity-workflow.ts` (PR #330 precedent). No new OAuth.

## 3. State & persistence

- **Anonymous:** allowed for public Tier B, Tier C, Tier A. Results client-side (+ localStorage draft of ratification answers); can download `.architecture/*` and the S7a zip; no history.
- **Signed-in:** persist `ScanRecord {repoRef, tier, verdict, artifacts, createdAt}`. **Sizing note (verified): this is a schema variant on `saved_projects`, not a field add** — `savedProjectBodySchema` requires `formState` + `manifestYaml`, which a scan record doesn't have. **Artifact bloat (review round 2):** the store is SQLite (`payload TEXT`, better-sqlite3) on the VPS data volume — no object store exists in this stack, so "push to S3/R2" is the wrong remedy. Instead: persist verdict + counts + the already-clipped report (`MAX_SCAN_REPORT_CHARS` = 32 k) + layout excerpt inline; write the handoff zip / full `findings.json` to the `/data` volume and keep only its path + size in the record; cap the inline findings array (e.g. first N entries + total) so a large monorepo never inflates a row. Re-scan appends records → platform-side trend, complementing the in-repo git-log trend (and covering Tier A, where the server never sees the repo). Org tenancy (hosting plan H1): ScanRecords keyed by org; the GitHub App becomes the org credential.

## 4. API + CLI surface

Existing: `POST /api/projects/scan` (zip, synchronous) — keep.

| ID    | New surface                         | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| API-1 | `POST /api/projects/scan/artifacts` | Tier A; parses handoff zip / loose files in-process. **No CLI dependency — ships regardless of D-P1.** Own tight limit profile (≤ 8 entries, small per-entry/total caps). **Unpacker note (applies to #558 too):** `unpackZipToDir` checks `maxEntryBytes` _after_ `entry.async("nodebuffer")` has fully inflated the entry — a single-entry bomb is buffered before it is rejected. Switch to `entry.nodeStream()` with a running byte counter that aborts at the cap; the compressed-size cap (32 MiB) bounds but does not prevent this. |
| API-2 | `POST /api/projects/scan/github`    | `{repoUrl, ref, tier}` → NDJSON stream (S2 hook consumes as-is). Clone bounded per §1.1a (API `size` preflight + size-capped tmpfs + wall-clock kill; `du` poll is secondary); `guardMutation` + anon `hxg_sid` cap + per-IP `checkRateLimit`. Gated on D-P1.                                                                                                                                                                                                                                                                              |
| API-3 | `POST /api/projects/bootstrap`      | Body = `BootstrapAnswers` + layout edits. | API-4 | `POST /api/projects/install-gate`   | `{scanId, mode}` → zip build, or branch+PR via the existing `/api/export/github` plumbing.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| API-5 | `GET /api/projects/:id/scans`       | History/trend.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| CLI-1 | **Machine-readable findings**       | `hexagen scan`/`hexagen-lint` emit a structured `findings.json` (rule, file, specifier, layer) into stdout JSON + the handoff zip. **Prerequisite for S5** — today no violations array crosses the seam. Pairs naturally with the already-planned machine-readable PR verdicts (strategy F9).                                                                                                                                                                                                                                              |
| CLI-2 | `bootstrap --propose-edges`         | Strategy F7; S4 prefill. Tier A (API-1/3) ships regardless; fixing the image is urgent independent of this plan.
