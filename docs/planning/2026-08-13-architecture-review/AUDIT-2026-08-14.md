# Adversarial audit of the 2026-08-13 architecture review

**Date:** 2026-08-14
**Method:** 76-agent adversarial workflow — one refuter per finding (64), six document
auditors (scorecard math, backlog topology via programmatic DFS, ADR-candidate conflicts
vs `.architecture/decisions/`, inventory toolchain claims, coverage honesty, phase-2
process claims), six blind-spot hunters over areas the review under-covered.
All verdicts verified against `main` at `7b2c7248`.

**Inputs audited:** the six files in this folder (`ARCHITECTURE-REVIEW.md`, `BACKLOG.md`,
`ADR-CANDIDATES.md`, `COVERAGE.md`, `findings.json`, `inventory.json`).

**Consumer:** `../2026-08-14-architecture-remediation-plan.md` — the remediation plan is
built from this audit, not from the review's raw claims.

**One-sentence verdict:** trustworthy for _where_ and _what_; not trustworthy for
_how bad_, _in what order_, or _is that everything_.

The dominant failure mode is a consistent overstatement signature: accurate quotes,
exaggerated hazard — neutralized in reality by TypeScript structural typing (the
port-homonym cluster), by the flagged code being dead (phantom `proposePR`, unused
`getActiveBackend`, unconsumed port copies), or by composition roots doing exactly
their job (env-derived LLM chains in `wire.server.ts`).

## 3. Findings the review missed (AUD-001 … AUD-022)

Seven of these are **high** — after regrading, they outrank everything in the review
itself. IDs are assigned here and used by the remediation plan.

### apps/web API routes + composition roots

- **AUD-001 (high)** — `wire.server.ts:569-570,613-615`: `getModifyArchitectureUseCase`
  skips the cache when SSE callbacks/signal are provided but **unconditionally** writes
  the new instance into `cachedUseCase`. After any `/api/architecture/modify/stream`
  request, the process singleton is the SSE-wired instance: later plain requests emit
  step events into a closed `ReadableStream` and inherit an already-fired abort signal.
  Contradicts the function's own doc comment.
- **AUD-002 (high)** — all four modify routes validate `manifestPath` against
  `process.cwd()` (= `apps/web`) while the adapters anchor on `findMonorepoRoot()`.
  The validation guards nothing (mutation adapter ignores the path entirely), and
  `restoreFromGit` **does** use it → nonexistent pathspec → `git checkout --` fails →
  on accept-with-lint-failure the bad patch stays applied and the route 500s; on reject
  the rollback is never reached (transaction stuck `speculative`). The compensation half
  of the accept/reject saga is structurally broken.
  (`accept/route.ts:10-25,109-113,142-167`; same copy in reject/stream/modify;
  `sync-delegating-manifest-mutation.adapter.ts:49-91`; `wire.server.ts:59-92`.)
- **AUD-003 (high)** — the architecture-modify family is unauthenticated with
  `Access-Control-Allow-Origin: *` (modify + accept) while it applies patches to the
  server's live `.architecture/manifest.yaml` and shells out (`yarn lint:arch`,
  `git checkout`) on any anonymous POST. Zero `getServerSession`/`checkRateLimit`/
  quota references under `app/api/architecture/` and `app/api/governance/` — a glaring
  inconsistency with the gated `/api/llm/chat`, `/api/plan/extract-decisions`, and
  manifest/generate routes.
- **AUD-004 (medium)** — the accept/reject commit-rollback saga (state-machine check,
  unchecked `tx.metadata.patches as Patch[]` cast, applyPatches → lint gate →
  git-restore compensation → commit/rollback) lives inline in HTTP handlers; no
  `AcceptTransaction`/`RejectTransaction` use case exists. `validateManifestPath`
  copy-pasted 4×, the CORS block ~10×.
- **AUD-005 (medium)** — governance is a shadow rules engine triplicated across
  `violations`/`status`/`refresh` routes with mutually divergent semantics (status
  counts manifest keys, refresh counts `.ts` files on disk; the two violation endpoints
  disagree), and **YAML parse failure returns `isCompliant: true`**.
- **AUD-006 (medium)** — two hand-rolled module-level `Map` rate limiters (llm/chat,
  plan/extract-decisions) that never evict idle keys and key on raw spoofable
  `x-forwarded-for`, coexisting with the shared `lib/rate-limiter.ts` that already
  solves eviction and hashing.
- **AUD-007 (medium)** — BYOK production wiring (`apps/web/app/lib/byok-wire.ts:15-58`)
  uses `InMemoryKeyMetadataAdapter`, `InMemoryRevocationAdapter`, and
  `ConsoleAuditLogAdapter` as the durable security store: a revoked compromised key
  silently un-revokes on every restart/redeploy. (COVERAGE.md had `byok` in its
  grep-only tier — the undisclosed thin-coverage risk materialized.)

### packages/external-integration

- **AUD-008 (medium)** — the context's entire declared auth hexagon (3 use-cases,
  3 inbound ports, 2 driven ports, 3 domain VOs) is dead code with zero adapters and
  zero consumers; real GitHub auth is NextAuth in apps/web (ADR-0046). Meanwhile the
  live capabilities (scaffold export, editor push) bypass the context's application
  layer. The governance manifest validates fiction.
- **AUD-009 (medium)** — `GitHubVcsAdapter.createPullRequest` hardcodes
  `owner:'organization'`, ignores its manifest argument, and references a branch that
  is never created — it can never succeed. Publicly exported, declared live in
  context.yaml, sole user of the production dependency `@octokit/rest`.

### packages/sync + tools/arch-linter (the published toolchain)

- **AUD-010 (high)** — architecture linting is advisory-only in host CI: no workflow
  runs lint at all; the only path is `cli sync` with `strict: options.strict ?? false`
  (`cli.ts:91`), so `linter.ts:52-55` logs failures and merges green. The step named
  "Verify Architectural Rules After Sync" (`sync-integrity.yml:50-51`) runs
  `--dry-run`, which short-circuits **before** the linter (`linter.ts:18-21`) — it
  verifies nothing. 30s exec timeout adds a silently-swallowed failure mode.
- **AUD-011 (high)** — the linter's layer-rules engine unconditionally allows relative
  intra-package imports, node builtins, and npm packages in domain/application
  (`tools/arch-linter/src/index.ts:351-394`) — exactly the violation classes the review
  found rampant. Run against the host it reports "Architecture is compliant." Generated
  projects have no compensating guard.
- **AUD-012 (medium)** — ts-morph five-major skew between the two co-published
  packages (sync `^22`, bundled TS 5.4.2 parser, vs arch-linter `^27`); every generated
  project installs both.
- **AUD-013 (medium)** — `@hexagen/sync`'s published root barrel exports
  `InMemoryConfigDouble` (a test double), `yaml-config.adapter`, and raw `fs-utils` as
  public API.

### Staged-generation pipeline

- **AUD-014 (medium)** — Stage-6 advisory copy is a load-bearing free-text protocol:
  the web classifies warnings by **prefix-matching English sentences** plus `(R12)`
  markers (`import-project-spec/utils.ts:205-236`); the canonical strings are
  duplicated verbatim in both orchestrators
  (`execute-structured-config-generation.use-case.ts:2458,2476,2490`;
  `execute-full-staged-generation.use-case.ts:265,277`); the keep-in-sync comment
  points at the wrong files. **This — not HEX-011 — is the real prerequisite for
  splitting GOD-001.**
- **AUD-015 (medium)** — the post-Stage-4 invariant-repair sequence is hand-duplicated
  across both orchestrators and has already drifted: R02 inbound-port synthesis exists
  only in the structured path.
- **AUD-016 (medium)** — R03 repair naming diverges: server synthesizes
  `<Aggregate>RepositoryPort` while the client fixer synthesizes
  `<PascalCaseContextName>RepositoryPort` — round-trips do not converge on one name.
  (`manifest-violation-fixer.ts:39-60` vs `synthesize-repository-ports.ts:26,55-75`.)

### Domain-purity sweep

- **AUD-017 (medium)** — manifest-generation _domain_ hosts the Generate-with-AI
  screen-flow state machine (`model-selection-state-machine.ts`) and end-user device
  error copy (`model-verification-service.ts`), type-coupled to
  `@hexagen/local-llm/client`. (Otherwise the sweep was **clean**: zero unindexed
  fs/axios/fetch/react/process.env/infrastructure hits across 34 non-template domain
  dirs.)

### Test-reality

- **AUD-018 (high)** — 24 "infrastructure/adapters" suites across 9 packages test only
  the `EchoFakePort` double (`packages/shared/src/testing/index.ts:27`,
  `unknown → unknown`, no `implements`) — they test the mock. In 5 packages
  (architectural-enforcement, code-generation, deployment, monaco-orchestration,
  persistence) these are the **only** tests: `turbo run test` reports them green while
  exercising nothing.
- **AUD-019 (high)** — the "3-layer information state firewall" layers 2–3 are never
  enforced: no workflow invokes lint, `lint:arch`, or `validate-ui-boundary.sh`
  (whose header claims a CI merge-gate role). Only bypassable pre-commit lint-staged.
- **AUD-020 (medium)** — `typecheck:test` defined in 15 packages, run by no workflow;
  the entire `__tests__` tree compiles unchecked in CI.
- **AUD-021 (medium)** — turbo test graph holes: api-gateway's test script is
  `echo "No tests configured"`; shared, llm-driver, model-settings, runtime, and
  apps/tui have no test target (llm-driver contains the hang-prone retry helper
  MOD-008 flags — untested).
- **AUD-022 (low)** — coverage thresholds exist only in a root c8 script no workflow
  invokes; no vitest coverage config anywhere.
