# Brownfield workbook: implementation plan

**Date:** 2026-10-01
**Status:** plan. Merging this document adopts the recommendations in §3 as the decisions of record. The owner can overturn any one of them by editing its row before a lane that waits on it is dispatched.
**Wave id:** `brownfield-workbook-w03`
**Input:** the owner's feature proposal "Brownfield Workbook — Feature Plan" (2026-10-01, kept outside the repo; cited below as _proposal §n_). The proposal was given an adversarial review against `origin/main` at `1c1a1f87`, and this plan is built on that review.

## 1. Goal and doctrine

An FDE opens a client repo they do not control. They see what is already there, bind an agent to a slice of it, and leave behind a gate and evidence. Greenfield stays as it is. Brownfield is a second workbook mode, not a conversion of the greenfield flow.

The doctrine is the proposal's, unchanged:

1. **Observed is separate from proposed.** What the scan found is drawn in the repo's own names. Slice and contract are drawn beside it, never in place of it. Nothing is badged with a type, layer or plane the scan did not observe.
2. **Files win.** Every step reads or writes a file that the CLI can also write. If a step works only in the web app, it is out of scope. A workbook whose contract exists only in a database cannot be left behind.
3. **No second write path.** In brownfield mode, every agent write goes through one grant check. A UI call outside the grant has no softer path.
4. **CLI first.** Every step must still work with the web app deleted.

## 4. Formats

These are defined in BW0 as types in `@hexagen/shared` plus JSON Schemas under `docs/kernel/`, before any producer or screen exists. They follow the same approach as the earlier arc, which shipped `scan-envelope.ts` before any screen.

1. **Mode.** `mode: "greenfield" | "brownfield"` on `savedProjectBodySchema` (`apps/web/lib/platform/saved-project-body.ts`) and on `SavedProject`. The schema is `.passthrough()`, so the field is additive. Every reader defaults an absent field to `"greenfield"`. A workbook has one mode, and nothing converts between modes.
2. **Observed report, `.hexagen/observed.json`.**
   - Shape: `{schemaVersion, repo:{remote?, commit}, generatedAt, packages[], languages[], build[], generated[], dontTouch[], edges[], unknown[], limits}`.
   - `packages[]`: `{name, root, manifestFile}`, using the repo's own names.
   - `edges[]`: `{from, to, kind: "import" | "unknown", specifier}`, where `from` and `to` are repo-relative file paths, or package roots when resolution stops at a package.
   - Every section has a `collected: false` arm with a reason, following `ScanFindings`.
   - There is no `type`, layer, plane or context field anywhere in the format, and the schema forbids extra properties.
3. **Slice, `.hexagen/slice.json`.** `{schemaVersion, id, repo:{remote?, commit}, paths:[prefix], excludes:[prefix], createdBy, createdAt}`. Prefixes are repo-relative and normalised to a trailing `/`, so `packages/bill/` never matches `packages/billing/`. A file prefix is stored as an exact path. Default deny outside `paths`.
4. **Contract, `.hexagen/contract.json`.** `{schemaVersion, sliceId, rules:[{id, kind:"forbid" | "allow-only", from:prefix, to:prefix, severity}], knownViolations:[{rule, file, specifier}]}`. The `knownViolations` entry shape reuses the ratchet baseline (`arch-lint-baseline.json`, `ratchet-baseline.ts`).
5. **Grants, `.hexagen/grants/<id>.json`.** The existing Field Kit `grant.schema.json`. `contexts` is omitted on a client repo. The grant schema has `additionalProperties: false` and no slice field, so the slice is linked through the trace: each trace line's existing `goal_id` carries the slice id.
6. **Trace, `.hexagen/evidence/trace.jsonl`.** As today, plus `seq` and `prev_hash` (BW-D8), and nullable `grant_id` for the two missing-grant halt reasons.
7. **Proposals, `.hexagen/proposals/<id>.patch` with `<id>.json`.** The patch plus `{id, grantId, tool, paths[], traceSeq, createdAt}` (BW-D9).
8. **Workbook bundle.** A zip written by `hexagen workbook export` containing items 2 to 7, a `bundle.json` index, and the pack HMAC. The web ingests it under the existing zip caps (`zip-unpack.ts`: 20k entries, 32 MiB per entry, 256 MiB in total).

## 6. Acceptance

These are _proposal §10_, restated so each one can be built and tested, with the lane that owns it.

1. **Their names, no invented type.** `hexagen observe` on a messy public fixture uses the repo's own package names. The output contains no `type`, layer or plane (BW0's schema test, BW4's fixture test). The viewer renders no badge that is missing from `observed.json` (BW8).
2. **An out-of-slice proposal is denied, visibly.** With the slice excluding package X, `hexagen_propose_patch` touching X is denied, a trace line records the denial, and the viewer's right panel and left rail show it (BW10, BW9). The same holds when no grant is passed, which today writes no line (BW3).
3. **The file is the truth.** The grant on disk is byte-identical to what the viewer shows (BW8). Flipping a path in the file after issue makes `grant check` deny with a signature failure. `grant revoke` makes it deny with `grant_revoked` (BW2).
4. **Delete the web app.** Every step works from the CLI: checkout (`git clone`), `observe`, `slice`, `contract`, `grant issue\|show\|check\|revoke`, `hexagen_propose_patch` through a local MCP client, `evidence pack`, `workbook export`. An end-to-end test drives this sequence on a fixture with no web app (BW7 owns the test, after BW2, BW3, BW5 and BW10).
5. **No generate on their tree.** No brownfield command calls `adopt`, `bootstrap` or `sync`. A test asserts that the client fixture's tree, apart from `.hexagen/` and `.git/info/exclude`, is byte-identical after the whole sequence in item 4 (BW7). The web's generate, accept and push routes refuse brownfield projects (BW6).
6. **Evidence cannot be quietly edited.** Deleting, reordering or editing one trace line makes `evidence pack` exit non-zero and write no passing bundle (BW3).

## 7. Out of scope

- **The earlier brownfield arc's open items.** Tier B never dispatches `SCAN_COMPLETE` (`GithubScanPage.tsx`). The web scan adapter does not parse `findings`.
