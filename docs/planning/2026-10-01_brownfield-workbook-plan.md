# Brownfield workbook: implementation plan

**Date:** 2026-10-01
**Status:** plan. Merging this document adopts the recommendations in §3 as the decisions of record. The owner can overturn any one of them by editing its row before a lane that waits on it is dispatched.
**Wave id:** `brownfield-workbook-w03`
**Input:** the owner's feature proposal "Brownfield Workbook — Feature Plan" (2026-10-01, kept outside the repo; cited below as _proposal §n_). The proposal was given an adversarial review against `origin/main` at `1c1a1f87`, and this plan was given a second one; §8 records what that second review changed.

## 1. Goal and doctrine

An FDE opens a client repo they do not control. They see what is already there, bind an agent to a slice of it, and leave behind a gate and evidence. Greenfield stays as it is. Brownfield is a second workbook mode, not a conversion of the greenfield flow.

The doctrine is the proposal's, unchanged:

1. **Observed is separate from proposed.** What the scan found is drawn in the repo's own names. Slice and contract are drawn beside it, never in place of it. Nothing is badged with a type, layer or plane the scan did not observe.
2. **Files win.** Every step reads or writes a file that the CLI can also write. If a step works only in the web app, it is out of scope. A workbook whose contract exists only in a database cannot be left behind.
3. **No second write path.** In brownfield mode, every agent write goes through one grant check. A UI call outside the grant has no softer path.
4. **CLI first.** Every step must still work with the web app deleted.

## 4. Formats

These are defined in BW0 as types in `@hexagen/shared` plus JSON Schemas under `docs/kernel/`, before any producer or screen exists. This follows the earlier arc, which shipped `scan-envelope.ts` before any screen.

1. **Mode.** `mode?: "greenfield" | "brownfield"`, optional, on `savedProjectBodySchema` (`apps/web/lib/platform/saved-project-body.ts`), on `SavedProject` (`packages/shared/src/domain/saved-project.ts`), and in the web narrowing in `apps/web/app/hooks/useSavedProjects.ts`. Every reader defaults an absent value to `"greenfield"`, so existing rows load unchanged. A workbook has one mode, and nothing converts between modes.
2. **Observed report, `.hexagen/observed.json`.**
   - Shape: `{schemaVersion, repo:{remote?, commit}, generatedAt, packages[], languages[], build[], generated[], dontTouch[], edges[], unresolved[], limits}`.
   - `packages[]`: `{name, root, manifestFile}`. The name is exactly as written in the package manifest, scope included.
   - `edges[]`: `{from, to, specifier}`. `from` is a repo-relative file and `to` is a repo-relative file or package root.
   - `unresolved[]`: `{from, specifier, reason}`, so an unresolved import is never dropped.
   - Each section has a `collected: false` arm with a reason, as `ScanFindings` does. A language the import pass does not read marks its edges `collected: false`, so an empty edge list never reads as a clean tree.
   - No `type`, layer, plane or context field exists anywhere in the format, and the schema forbids extra properties.
3. **Slice, `.hexagen/slice.json`.** `{schemaVersion, id, repo:{remote?, commit}, paths:[prefix], excludes:[prefix], createdBy, createdAt}`. A path is repo-relative and case-sensitive. An entry ending in `/` is a directory prefix, and any other entry is an exact file path. Segments `.` and `..`, absolute paths, backslashes and NUL are refused. Everything outside `paths`, or inside `excludes`, is denied.
4. **Contract, `.hexagen/contract.json`.** `{schemaVersion, sliceId, rules:[{id, kind:"forbid" | "allow-only", from:prefix, to:prefix, severity}], knownViolations:[{rule, file, specifier}]}`. The `knownViolations` entry shape reuses the ratchet baseline (`tools/arch-linter/src/ratchet-baseline.ts`). An unresolved in-slice specifier is a violation of the built-in rule id `unresolved-import`.
5. **Grants, `.hexagen/grants/<id>.json`.** The Field Kit `.hexagen/grant.schema.json` gains the `signature` property (copied from `docs/kernel/grant.schema.json`), because today it cannot describe a file `grant issue` writes. A client grant **omits** `contexts`; it does not write `[]`. `canonicalGrantPayload` in `packages/sync/src/commands/grant/canonical.ts` and its twin in `grant.ts` must serialise an absent `contexts` identically. `JSON.stringify` already drops `undefined`, and a test pins that both functions agree byte for byte. The schema has `additionalProperties: false` and no slice field, so the slice is linked through the trace's `goal_id`.
6. **Trace, `.hexagen/evidence/trace.jsonl`.** Today's line, plus `seq` and `prev_hash`, the `grant_missing` record kind, and `tip.json` (BW-D8).
7. **Proposals, `.hexagen/proposals/<id>.patch` with `<id>.json`.** The patch plus `{id, grantId, sliceId, tool, paths[], traceSeq, createdAt}` (BW-D9).
8. **Workbook bundle.** A zip written by `hexagen workbook export`: items 2, 3, 4, 5, 7, the packed evidence and `tip.json`, a `bundle.json` index, and the pack HMAC. The export allow-list never includes a key file, anything under `~/.hexagen/keys/`, or `.hexagen/grant-signing.key`.

## 6. Acceptance

These are _proposal §10_, restated so each can be built and tested, with the lane that owns each one. BW1 (the adapter) and BW5 (slice and contract) are prerequisites for items 2 and 4.

1. **Their names, no invented type.** `hexagen observe` on a messy public fixture keeps package names exactly as written. Its output contains no `type`, layer or plane (BW0's schema test, BW4a's fixture test). The viewer renders no badge that is missing from `observed.json` (BW8).
2. **An out-of-slice proposal is denied, visibly.**
   - Owners: BW10, plus BW7b's Evidence step and BW9.
   - With the slice excluding package X, `hexagen_propose_patch` touching X is denied, even under a grant that lists X.
   - A trace line records the denial.
   - The viewer shows it in the right panel and in the left rail's Evidence step.
   - A call with no grant writes a `grant_missing` record, which today writes nothing (BW3).
3. **The file is the truth.** The grant on disk is byte-identical to what the viewer shows (BW8). Flipping a path in the file after issue makes `grant check` deny with a signature failure. `grant revoke` makes it deny with `grant_revoked` (BW2b, BW2c).
4. **Delete the web app.** Every step works from the CLI and a local MCP client. BW7a's end-to-end test drives the whole sequence on a fixture with no web app.
5. **No generate on their tree.** No brownfield command calls `adopt`, `bootstrap` or `sync`. BW7a's end-to-end test asserts the client tree is byte-identical apart from `.hexagen/` and the exclude file. The web's generate, accept and push routes refuse a brownfield project, and the viewer never mounts them (BW6).
6. **Evidence cannot be quietly edited.** `evidence pack` exits non-zero and writes no passing bundle if any of these happen (BW3):
   - one line is edited, reordered or deleted;
   - the tail is truncated below the recorded tip;
   - the file is restarted from genesis.
7. **TUI.** The `--brownfield` TUI view shows the slice, `grant show` output and the trace tail, and never offers the `r` action (BW11).

## 7. Out of scope

- **The earlier brownfield arc's open items:**
  - Tier B never dispatches `SCAN_COMPLETE` (`GithubScanPage.tsx`);
  - the web scan adapter does not parse `findings`;
  - the ratified manifest is never POSTed to bootstrap.

  These belong to the existing import wizard, which this plan leaves as it is. They are follow-ups for that flow, not lanes here.

- **Deferred decisions:** `mode: "write"` for patches, client-org PRs (BW-D6), the hexagonal new-package action (BW-D10), multiple slices per workbook, and a revocation list (BW-D5).
- **Offline use:** the kit is local. Known online dependencies are documented, not removed: the TUI's `r` action calls a hosted model, report HTML loads Mermaid from a CDN, and Tier B needs GitHub.
- **Orchestration bins inside the workbook** (_proposal §8_).

## 8. Second review

A second model review of this plan found six blockers and five should-fix items. Its file-and-line checks were confirmed by hand before anything was changed. This version incorporates them:

- **One key path, shared everywhere.**
  - The MCP verifier read only the in-repo key.
  - The engagement id was undefined.
  - Issuing a grant before the slice existed would still have minted a key into the client tree.

  Fixed in BW-D4 and BW2a.

- **The Field Kit grant schema lacked `signature`.** An absent `contexts` and `[]` sign differently. Fixed in §4.5 and BW0.
- **The hash chain anchors its tip.** A per-line chain alone missed tail truncation and a restart from genesis. Denials also keep today's skip of the allowlist and window checks, because a real denial violates them. Fixed in BW-D8 and BW3.
- **The slice is enforced, not only the grant.** A grant wider than the slice could otherwise allow an out-of-slice patch. Fixed in BW-D9, BW2a and BW10.
- **Unresolved imports fail `contract check`.** Otherwise a green check could mean "the pass saw nothing". Fixed in BW-D3, BW4b and BW5.
- **The bundle is parsed in the browser.** It is never sent through the server-side Tier A unpacker, whose caps are 8 entries and 4 MiB, and the viewer does not claim an HMAC check it cannot perform. Fixed in BW-D2 and BW7b.
- **Smaller fixes:**
  - the exclude file is resolved with `git rev-parse --git-path`;
  - path, rename and symlink rules are applied before matching;
  - BW7a waits on BW10, and the Evidence step owns the left-rail trace;
  - BW2, BW4 and BW7 are split into smaller lanes;
  - the migration and the doc edits are named;
  - package names are corrected.

Two of its claims were narrowed rather than adopted:

- **Grant canonicalisation:** the payload already drops an absent `contexts` (`JSON.stringify` skips `undefined`), so the plan asks for a test that pins this, not for new code.
- **Package names:** the source names are `@hexagen/*`, and the plan names the published `@hexagen-monaco/sync` alongside them.
