# Hosting migration plan — users, teams, server-side projects

**Date:** 2026-08-20 · **Status:** decision-ready; feasibility-reviewed against the tree (five implementation defects found and folded in below — every other named file/module was verified to exist as claimed)
**Companion:** FDE strategy / licensing brainstorm (kept out of the repo; owner holds the document)
**Baseline:** `origin/main` @ `4dddf1e1`; prod = single VPS container `hexagen-web`, three better-sqlite3 files on volume `hexagen-monaco-quota-data` → `/data` (quota.db, byok.db, platform.db)

**Scope.** Evolve the existing platform seam (`apps/web/lib/platform/*`, PR #531) from single-user hosted accounts to org/team tenancy, server-authoritative projects, run history, and live billing. The CLI/CI wedge (`tools/arch-linter`, `packages/sync`) is untouched. **Principle: extend the seam, don't rebuild** — auth, owner-scoped stores, project routes, the IDB fallback, and the billing seam all already exist and were verified live.

**Standing decisions honored.** ADR-0065: single-container compose is canonical; Wave H3 below _is_ the "Phase 2 multi-tenancy" trigger that ADR reserves — Postgres/replicas require amending it first (gate D-H4). ADR-0063: the 8 metering route files are frozen; entitlement enforcement on generate routes goes through D-H3. ADR-0030: BYOK ciphertext never persists server-side — retained verbatim. Deploys and release tags stay owner-gated.

---

## What already works (verified; do not rebuild)

- **Auth is real, not stubbed:** NextAuth GitHub OAuth (`app/lib/auth.ts`), JWT sessions, custom sqlite adapter (`lib/platform/auth-store.ts`); GitHub token lives only in the JWT server-side. Tables: users/accounts/sessions/verification_tokens.
- **Saved projects work end-to-end for signed-in users:** `app/api/projects` + `[projectId]` routes (optimistic concurrency via `If-Match: updatedAt`), `saved-projects-store.ts`, and the client's `CachedSavedProjectsAdapter(IDB, HTTP)` — server-authoritative with silent IDB fallback for anonymous users, one-time IDB→server lift on first sign-in (implemented in `app/lib/adapters/http-saved-projects.adapter.ts:276–290`, keyed on the `project_owner_state.initialized` flag), owner-mismatch cache wipe, salvage-on-read (`salvage-session-fields.ts`).
- **Run history works for signed-in users:** fire-and-forget stage telemetry → `POST /api/runs` (upsert per owner/run/stage, cost from `model_prices`), `RunHistoryPage` with 14-day trend.
- **Billing is a seam:** `lib/platform/billing.ts` plans (`free`/`repo` $29), `EntitlementRepository`, `readStripeConfig`, `STRIPE_*` already in `deploy/.env.example` — but no Stripe SDK, no checkout/webhook, nothing writes or consults entitlements in prod paths.
- **Tenancy primitive:** every SQL statement bakes in `owner_id` (JWT `sub`); PK `(owner_id, id)`. This is the load-bearing trick below.

## Gaps this plan closes

No teams/orgs/sharing (tenant = single JWT sub) · billing enforcement absent · signed-in users have no metering identity (anon-cookie-only) · single-process sqlite + in-memory rate limiter + in-process modify-flow transaction state block >1 replica · no backup/restore or data export · wizard drafts/workspace remain device-local IDB.

## Auth & session (standing choice, not a wave)

**Keep NextAuth GitHub OAuth as the sole v1 provider.** It fits the planned GitHub-login subscription gate; scopes already serve publish (ADR-0046); and ADR-0063's "OAuth = authorization, not entitlement" holds — entitlement derives from the `entitlements` table (Stripe-driven), never from login. **JWT session strategy stays** (no per-request session reads; replica-friendly for H3). Org context is **not** embedded in the JWT — membership resolves per-request from DB so removal takes effect immediately. Email/password and SSO/SAML: out (SSO is the Platform-tier promise). → D-H1.

## Wave H1 — Orgs/teams (~2–3 wk)

**The tenancy trick that keeps the seam intact:** `owner_id` is an opaque UUID baked into every prepared statement (`PlatformStore.projectsFor/runsFor`; PK `(owner_id, id)` — feasibility-verified). **An org is just another owner:** org rows use the org UUID as `owner_id` — zero store-schema churn; authorization moves entirely to membership resolution.

## Out of scope

Realtime co-editing/CRDT · SSO/SAML + fine-grained RBAC (Platform tier) · self-hosted enterprise (FCL question, ADR-0061/0067) · email auth · k8s (deleted, ADR-0065) · any change to anon quota policy or the spec→convert double-charge (ADR-0063) · wedge licensing (companion doc §1) · marketing assets.
