# P2.2: Auto-Update Linter Config - Design Specification

**Status:** Design Complete - Ready for Implementation
**Priority:** P2 (Developer Experience Enhancement)
**Estimated Effort:** 3 hours
**Created:** 2026-04-28

---

## Problem Statement

When adding a dependency to `.architecture/manifest.yaml`, developers must manually update `.architecture/invariants/linter-config.yaml` to add the dependency to the `allowed_imports` list. This creates:

1. **Validation loops** - `yarn lint:arch` fails even with dependency declared
2. **Manual synchronization burden** - 10-15 edits per new cross-package dependency
3. **Drift risk** - Linter config can become stale if updates are forgotten

boundedContexts:
  - name: mcp-server

### Linter Config Structure (`.architecture/invariants/linter-config.yaml`)

```yaml
package_rules:
  - name: "mcp-server"
    allowed_imports:
      - "@hexagen/shared"
      - "@hexagen/messaging"
      - "@hexagen/project-configuration"
      - "@hexagen/governance"
      - "@hexagen/visualization"
      - "@hexagen/report-governance"

    # Comments explaining rationale
```

## Proposed Solution

### Architecture

**Location:** `packages/sync/src/linter-config-sync.ts`

**Integration Point:** Called automatically during `yarn sync` after manifest mutations

**Dependencies:**

- `yaml` package (already in sync dependencies)
- `packages/sync/src/manifest-service.ts` (for manifest reading)
- `packages/sync/src/fs-utils.ts` (for file operations)

### Algorithm

```typescript
interface LinterConfigSyncResult {
  updated: boolean;
  packagesModified: string[];
  errors: string[];
}

async function syncLinterConfig(
  manifestPath: string,
  linterConfigPath: string,
  options: { dryRun?: boolean; preserveComments?: boolean },
): Promise<LinterConfigSyncResult>;
```

**Steps:**

1. **Parse Manifest**
   - Extract all `boundedContexts[].name` and `boundedContexts[].depends_on`
   - Build dependency map: `Map<string, string[]>`

2. **Parse Linter Config**
   - Load YAML with comment preservation (using `yaml` library's `parseDocument`)
   - Extract existing `package_rules`
   - Identify manual overrides (rules not in manifest)

3. **Compute Diff**
   - For each package in manifest:
     - Compare `depends_on` with `allowed_imports`
     - Detect additions (in manifest, not in linter config)
     - Detect removals (in linter config, not in manifest)
   - Flag manual overrides for preservation

4. **Apply Updates**
   - Add missing imports to `allowed_imports`
   - Remove stale imports (with confirmation if not in `--force` mode)
   - Preserve comments and formatting
   - Sort imports alphabetically

5. **Write Back**
   - Use `yaml.stringify()` with comment preservation
   - Atomic write (write to temp file, then rename)

### Comment Preservation Strategy

**Approach:** Use `yaml` library's `parseDocument()` which preserves comments as part of the AST.

```typescript
import { parseDocument, stringify } from "yaml";

const doc = parseDocument(linterConfigContent);
const packageRules = doc.get("package_rules");

// Modify while preserving comments
for (const rule of packageRules.items) {
  const name = rule.get("name");
  const allowedImports = rule.get("allowed_imports");

  // Add new imports while preserving existing comments
  const newImports = computeNewImports(name, manifestDeps);
  for (const imp of newImports) {
    allowedImports.add(imp);
  }
}

const updated = stringify(doc);
```

### Manual Override Detection

**Strategy:** Detect packages in linter config that don't exist in manifest, or imports that aren't in `depends_on`.

**Behavior:**

- **Preserve** manual overrides by default
- **Warn** about potential stale overrides
- **Remove** only with `--force` flag

## API Design

### Function Signature

```typescript
/**
 * Synchronizes linter-config.yaml with manifest.yaml dependencies
 *
 * @param manifestPath - Path to manifest.yaml
 * @param linterConfigPath - Path to linter-config.yaml
 * @param options - Sync options
 * @returns Result with updated packages and any errors
 */
export async function syncLinterConfig(
  manifestPath: string,
  linterConfigPath: string,
  options: {
    dryRun?: boolean;
    preserveComments?: boolean;
    force?: boolean;
  } = {},
): Promise<LinterConfigSyncResult>;
```

### CLI Integration

```bash
# Automatic sync during normal sync
yarn sync

# Skip linter config sync
yarn sync --skip-linter-sync

# Dry run to preview changes
yarn sync --dry-run

# Force removal of stale imports
yarn sync --force
```

## Edge Cases

### 1. Package in Linter Config but Not in Manifest

**Behavior:** Preserve (assume manual override), warn in output

### 2. Import in Linter Config but Not in depends_on

**Behavior:** Preserve (assume manual override), warn in output

### 3. Malformed YAML

**Behavior:** Fail gracefully, report error, don't modify file

### 4. Global Whitelist Entries

**Behavior:** Never modify `global_whitelist` section

### 5. Test Double Rules

**Behavior:** Never modify `test_double_rules` section
